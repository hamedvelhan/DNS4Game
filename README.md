# DNS Game Art — پیش‌نمایش وب و رابط نسخه Native

این پروژه یک پیش‌نمایش واکنش‌گرای وب با React، TypeScript و Vite است. پروژهٔ ارسالی شامل اپلیکیشن Kotlin/Android، فایل APK، موتور VPN واقعی، SDK تبلیغات واقعی یا SDK پرداخت مایکت نیست. رابط و منطق گردش‌کار در این نسخه اصلاح شده و برای تکمیل نسخهٔ اندروید، قرارداد پل Native در `docs/native-bridge.md` آمده است.

## اجرای پروژه در ویندوز و VS Code

۱. مخزن `DNS4Game` را Clone کنید و پوشهٔ آن را در VS Code باز کنید.
۲. ترمینال را از مسیر Terminal → New Terminal باز کنید.
۳. اجرا کنید:

```powershell
npm install
npm run dev
```

۴. آدرس محلی Vite را در مرورگر باز کنید.

ساخت خروجی وب:

```powershell
npm run typecheck
npm run build
```

## تغییرات این نسخه

- لمس هر نقطه از کارت سرور در تب سرورها، کارت پیشنهاد اسکن هوشمند یا کارت سرور انتخاب‌شده در خانه، همان مسیر را اجرا می‌کند: نمایش تبلیغ اتصال، تأیید خودکار پاداش و شروع اتصال بدون کلیک اضافه.
- پس از برقراری اتصال، برنامه مستقیماً داشبورد اتصال را نشان می‌دهد و تب خانه به‌عنوان تب بازگشت تنظیم می‌شود.
- قطع اتصال دستی برای حساب رایگان ابتدا تبلیغ را نمایش می‌دهد و پس از پایان یا بسته‌شدن تبلیغ، اتصال قطع می‌شود. در دسترس نبودن تبلیغ مانع قطع اتصال نخواهد شد.
- قطع خودکار پس از پایان زمان ۶۰ دقیقه‌ای بدون تبلیغ انجام می‌شود تا اتصال منقضی‌شده پشت تبلیغ باقی نماند.
- هر اتصال رایگان ۶۰ دقیقه اعتبار دارد. تکمیل دو ویدیوی جایزه‌ای، ۶۰ دقیقه اضافه می‌کند: اگر کاربر متصل باشد به همان نشست افزوده می‌شود و اگر قطع باشد برای اتصال بعدی ذخیره می‌شود.
- کارت افزایش زمان در داشبورد اتصال نیز قابل دسترسی است.
- شبکه با وضعیت آنلاین/آفلاین مرورگر، API نوع شبکه در صورت پشتیبانی و یک بررسی سبک دسترسی اینترنت تشخیص داده می‌شود. دکمهٔ تازه‌سازی تشخیص شبکه نیز اضافه شده است.
- اطلاعات اپراتور و نوع دقیق شبکه فقط از پل Native دستگاه قابل دریافت است؛ مرورگر وب معمولاً اجازهٔ خواندن نام اپراتور سیم‌کارت را نمی‌دهد.
- در کارت‌های سرور، وضعیت متنی عالی/خوب/ضعیف با مقدار عددی Jitter جایگزین شده و پایداری به درصد و نوار پیشرفت نمایش داده می‌شود.
- سبک کارت‌ها و عناصر گرافیکی به تم نئون/سایبرپانک نزدیک‌تر شده و نمودار داشبورد با سه خط تأخیر DNS، Jitter و Packet Loss جزئیات بیشتری دارد.
- تب حساب شامل ثبت‌نام/ورود آزمایشی، مدیریت حساب، خرید و بازیابی اشتراک مایکت و سابقهٔ خرید است. رمز عبور در پیش‌نمایش ذخیره نمی‌شود.
- دکمهٔ فعال‌سازی اشتراک آزمایشی حذف شده است. اشتراک فقط پس از پاسخ موفق SDK و تأیید رسید خرید توسط سرویس مورداعتماد فعال می‌شود.

## محدودیت‌های پیش‌نمایش وب

- تبلیغ شش‌ثانیه‌ای در مرورگر فقط نمایشی است و ویدیوی تبلیغاتی واقعی پخش نمی‌کند. در نسخهٔ Native، `RewardedAdProvider` باید به SDK تبلیغات متصل شود.
- مجوز VPN، راه‌اندازی DNS، نمونه‌برداری شبکه و آمار زنده در این نسخه شبیه‌سازی می‌شوند. مرورگر نمی‌تواند به‌جای Android `VpnService` تونل VPN واقعی بسازد.
- حسابی که بدون پل Native ساخته می‌شود فقط یک حساب نمایشی محلی است، نه ثبت‌نام سمت سرور. برای حساب واقعی باید پل احراز هویت به بک‌اند متصل شود.
- پرداخت درون‌برنامه‌ای مایکت در وب اجرا نمی‌شود. `purchaseMyket` و `verifyMyketPurchase` در `window.DNSGameArtNative` به‌عنوان قرارداد اتصال آماده شده‌اند. رسید باید سمت سرور و از مسیر معتبر فروشگاه بررسی شود؛ صرفاً پاسخ سمت کلاینت برای فعال‌سازی اشتراک کافی نیست.
- شناسهٔ محصول پیش‌فرض `dns_game_art_premium_monthly` است و باید دقیقاً با شناسه‌ای که در پنل مایکت برای محصول اشتراکی ثبت می‌شود مطابقت داده شود.
- آدرس‌های DNS کاتالوگ عمداً خالی هستند تا IP تأییدنشده وارد نشود. برای اتصال واقعی باید endpointهای معتبر و مجاز به کاتالوگ اضافه شوند.

## قرارداد پل Native اندروید

جزئیات متدهای موردانتظار برای شبکه، احراز هویت و خرید/بازیابی مایکت در فایل `docs/native-bridge.md` قرار دارد. پیاده‌سازی نهایی این متدها باید در پروژهٔ Android/Kotlin انجام شود و اعتبار خرید در بک‌اند تأیید شود.

## بررسی خودکار کد

با هر Push روی شاخه‌های `main` و `feature/*` و نیز هنگام Pull Request به `main`، GitHub Actions وابستگی‌ها را نصب می‌کند، TypeScript را بررسی می‌کند و خروجی Production با Vite می‌سازد.
